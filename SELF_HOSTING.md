# Self-hosting 4c

The active goal is to compile the existing `src/4c.c`, including
`src/softfloat.h` and `src/asm_comments.h`, with 4c on AArch64 Linux.
Keep the source readable and implement the C features it uses rather than
rewriting those features away. Generated code must still use the twelve allowed
instruction mnemonics. System assembly, linking, startup code, and libc remain
dependencies.

## Completion checks

1. Build stage 1 from this source with the system C compiler.
2. Use stage 1 to compile the same source and implementation headers; assemble
   and link its output to produce stage 2.
3. Use stage 2 to repeat that compilation and produce stage 3.
4. Compare assembly generated by stages 2 and 3 under identical options and
   source paths. Bootstrap convergence is necessary, but not sufficient proof
   of correctness.
5. Run the regression suite with the self-built compiler, including unchanged
   Dhrystone and cross-compiler ABI checks.
6. Audit the compiler-generated machine instructions, including its private
   arithmetic routines, against the twelve-mnemonic restriction.

## Bootstrap status

The bootstrap converges. With `include/softfloat.h` and `include/asm_comments.h`
copied into the controlled include directory so the compiler's own includes
resolve, the sequence below produces byte-identical assembly at the fixpoint:

```sh
make
cp src/softfloat.h src/asm_comments.h include/
./build/4c --target linux -I include src/4c.c -o /tmp/stage2.s   # stage 1 -> 2
cc /tmp/stage2.s -o /tmp/stage2
/tmp/stage2 --target linux -I include src/4c.c -o /tmp/stage3.s  # stage 2 -> 3
cc /tmp/stage3.s -o /tmp/stage3
/tmp/stage3 --target linux -I include src/4c.c -o /tmp/stage4.s  # stage 3 -> 4
cmp /tmp/stage3.s /tmp/stage4.s                                  # converges
```

The self-built compiler passes the full regression suite (111 tests, including
unchanged-source Dhrystone with real and controlled clocks) and its own object
code audits clean against the twelve-mnemonic whitelist under
`objdump -d -M no-aliases`. Bugs fixed along the way: callee-side stack-argument
offsets now walk cumulative byte offsets, `va_start` uses the correct
`__gr_offs = -8*(8-named)` and saves d0..d7, variadic `__VA_ARGS__` stringifies
every slice including the original commas, and global aggregate initializers
are laid out at true member offsets so inter-member padding is preserved.
Bootstrap convergence is necessary, but not sufficient proof of correctness.

The post-bootstrap review fixes are covered by cross-compiler tests in both
directions: indirect large-aggregate arguments, homogeneous double aggregates
and their results, and register exhaustion. Variadic cursor copies are checked
with independent GP/FP save positions and stack-passed arguments. The fixed-width
integer headers now use real signed/unsigned byte and 16-bit types, and macro
arguments are expanded before substitution except at stringification/pasting
sites. Stringification preserves token spelling and whitespace after expansion.
The normal, sanitizer and self-built compiler suites and bootstrap convergence
were rerun after these fixes; the generated compiler object retains the
twelve-mnemonic instruction vocabulary.

Each language feature has small executable regression examples and retains
explanatory emitted assembly. ABI changes were compared with system-compiled
callers/callees for every size class (8 bytes, 16 bytes, 32 bytes).

The completed Dhrystone milestone and its history remain in `TODO.md`.
Native macOS ABI work is separate from this Linux bootstrap milestone.

File-scope static linkage is implemented for objects and functions, including
prototypes and extern declarations that inherit internal linkage. A native link
test supplies external symbols with the same names to verify that static symbols
remain local. The current direct self-compilation attempt reaches `UINT64_C`,
which now has a controlled-header definition using token pasting. Compatible
object-pointer ordering and subtraction are also implemented and tested against
system C. The next direct self-compilation attempt hits the per-function
code-size limit. That guard now measures encoded instruction bytes in the
completed function body, including buffered loop steps, rather than assembly
text length. It includes literal-pool size and reserves space for function
setup/cleanup within the one-megabyte LDR/CBZ reach. A large native function
assembles and matches system-C execution. The direct self-compilation attempt
now passes the block-scope static keyword table in `identifier`. Block-scope
static storage is implemented with local symbols and tested for persistence
and shadowing. Expression-form sizeof now suppresses operand evaluation and
temporary code-generation state; tests cover side effects and uninitialized
pointers used solely for their type. The next direct failure is the missing
controlled declaration of `strtoull`; the numeric conversion declarations have
since been added and tested against libc. For-loop declarations now store their
initializers and restore their scope, and empty for headers and casts to void
work. The current direct attempt reaches `emit_init_entry(InitEntry e)` and
rejects its aggregate parameter. Aggregate ABI implementation is the next
bootstrap blocker.
New initializer,
preprocessor, sizeof and stdarg work in the source needs continued bootstrap
validation; its presence alone does not establish self-hosting.
